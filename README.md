# Amber

Личный офлайн-плеер для Android (делается под Galaxy S23 Ultra) и Windows. Помнит каждое прослушивание, ставит треки по местам в личном рейтинге, считает статистику. Всё работает без сети; по желанию телефон и компьютер синхронизируются через свой сервер.

Концепция, дизайн и план по фазам: https://claude.ai/artifact/QsKTaJBVvqP6dWmx3A5buF

## Что умеет

- **Библиотека:** сканирование mp3 и m4a (AAC) на телефоне — формат определяется по содержимому, а не по расширению, кириллица из CP1251, обложки, папки-исключения, альбомы, исполнители, жанры, папки, поиск с транслитом и раскладкой, алфавитная полоса.
- **Плеер:** мини-плеер тянется пальцем вверх в полный, свайп по нему и по большой обложке показывает соседний трек; фоновая служба с уведомлением и кнопкой ❤, экран блокировки, виджет, ярлыки на значке; очередь с перетаскиванием и историей; виды перемешивания; сон-таймер; скорость и тон (slowed / nightcore / slowed + reverb) и эффекты: эхо, зал, бас, ширина, 8D, «за стеной», радио, караоке — у каждого своя сила; свои пресеты звука (скорость + тон + эффекты под именем, включаются одним нажатием — кнопка звука всегда в нижнем ряду плеера); перемешивание и повтор сохраняются между запусками (на телефоне — свой процессор в звуке каждой деки, SoundEffects.kt; в браузере — узлы Web Audio); фон полного плеера — цвета, которых на обложке больше всего по площади (серые обложки остаются серыми); повтор отрезка A–B; метки и «лучшие моменты»; текст песни с подсветкой строки — из файла, свой или из открытой базы LRCLIB (lrclib.net): если в файле текста нет, подходящий вариант подставляется сам, не подошёл — другой из списка или свой.
- **Звук:** кроссфейд, наложение и затухание между треками (кривая стыка стартует, когда второй трек реально зазвучал, — без провала), смена скорости и тона без щелчков, альбомы без склеек, одинаковая громкость по анализу (EBU R128), 10-полосный эквалайзер с пресетами, профили под наушники и колонку, выбор вывода звука.
- **Оценки и рейтинг:** звёзды с половинками, места с движением за неделю, уточнение порядка перетаскиванием, дуэли (Эло), подсказки «поднять/опустить оценку», недельные чарты с архивом, пиком и неделями в чарте.
- **Статистика:** каждое прослушивание хранится сырым событием, правило «что считать прослушиванием» настраивается и пересчитывает всю историю; календарь, часы, серии; дневник с настроением и заметками, «в этот день», вехи; эпохи и сезоны с фирменным звучанием и «машиной времени»; контексты по времени, дням и устройству; итоги месяца и года историями с сохранением картинкой.
- **Подборки:** плейлисты в группах (папках) и закреплённые сверху; на компьютере всё перетаскивается мышью в меню слева — между собой, в группу и из неё, в закреплённые; на телефоне — пункты «Закрепить», «В группу…», «Поднять/опустить в списке» в меню по удержанию. Плейлисты с подбором треков прямо со страницы плейлиста и отметкой «уже в плейлисте», своей обложкой и меню по удержанию; плейлист превращается в микс и обратно (стыки сохраняются), умные плейлисты по условиям, миксы со своим переходом на каждом стыке (волна, точки перехода, прослушивание стыка), радио из своей музыки по похожести, автоподборки.
- **Теги:** правка в сами файлы — ID3 в mp3 и iTunes-теги в m4a, включая обложку (Android спрашивает разрешение); после записи файл перечитывается и сверяется, оригинал сохраняется, есть кнопка «Вернуть файл»; файлы, испорченные записью старых версий, находятся и чинятся. Уборка мусора сайтов и капслока, дубли со слиянием истории.
- **Удаление:** файл удаляется с телефона (Android спрашивает подтверждение), история и оценки остаются в статистике; в «Дублях» — «Слить и удалить лишние файлы».
- **YouTube** — единственная онлайн-функция: в поиске «Скачать с YouTube по ссылке» (или просто вставить ссылку). Звук сохраняется в «Музыка/Amber» с тегами и обложкой и дальше играет без сети. Разбор страниц — библиотека NewPipeExtractor (GPLv3); когда YouTube что-то меняет, нужна её новая версия.
- **Движение:** главные экраны — одна лента (главная → разделы медиатеки → поиск → вкладки топа → вкладки хроники). Соседние экраны уже отрисованы и едут за пальцем один в один: видно следующий, можно долистать или вернуть; отпустил дальше 40 % ширины или смахнул — перелистнулось. У разделов с подвкладками (медиатека, топ, хроника) заголовок и чипсы общие: при листании вкладок они стоят, подсветка чипса едет за пальцем, а в соседний раздел заголовок уезжает вместе с ним; большое название прячется при прокрутке, чипсы остаются. Чипсы, вкладки внизу и «назад» двигают ту же ленту, недавние экраны помнят прокрутку; в этих разделах строки треков свои свайпы не забирают — действия по удержанию или «⋯». Экраны въезжают вглубь и уходят назад, вкладки сменяются проявлением, обложка перелетает из карточки на страницу альбома или исполнителя; анимации кнопок и иконок. Касание, остановившее прокрутку, ничего не нажимает, ползунки и звёзды реагируют только на движение вбок.
- **Данные:** экспорт и импорт одним JSON, ежедневный автобэкап в выбранную папку.
- **История Spotify** (Настройки → Spotify): загружаешь выгрузку «Расширенная история» — архив my_spotify_data.zip или JSON-файлы из него, — и она добавляется в статистику: время, календарь, часы, серии, дневник, эпохи, итоги, а треки, которые нашлись в медиатеке (по исполнителю и названию), получают свои прослушивания. Переключатель «Показывать в статистике» убирает и возвращает её в любой момент, ничего не удаляя. Подкасты и видео пропускаются, повторная загрузка не дублирует; правило «что считать прослушиванием» действует и на неё. Недельные чарты, радио и автоподборки считаются только по прослушиваниям в Amber. История Spotify хранится на устройстве: не синхронизируется и не попадает в бэкап.
- **Синхронизация** (по желанию): аккаунт на своём сервере, и оценки, история, плейлисты, эпохи, контексты, дневник и общие настройки сами ходят между телефоном и компьютером — сразу: включил трек на компьютере, и через секунду после конца он уже в истории на телефоне. Без сети изменения копятся и уходят молча, когда связь появится. Треки на сервер не попадают. Сервер и как его развернуть — [server/README.md](server/README.md).

## Как устроено

- **Интерфейс и вся логика** — Vue 3 + TypeScript, папка `src/`.
- **Звуковой движок** — Kotlin, папка `android/app/src/main/java/app/yantar/player/`.
  Фоновая служба Media3 (шторка, экран блокировки, часы, кнопки наушников), две деки ExoPlayer для переходов, эквалайзер и нормализация (DynamicsProcessing), анализ громкости, учёт прослушиваний, сканер библиотеки, запись тегов, SQLite.
- **Граница между ними** — один Capacitor-плагин `MusicCore`:
  TS-сторона `src/native/music-core.ts`, Kotlin-сторона `core/MusicCorePlugin.kt`.
- **Веб-версия движка** `src/native/web/` повторяет Kotlin-часть на Web Audio: две деки, переходы, нормализация, эквалайзер, анализ в Web Worker. Играет демо-библиотеку или папку с твоими mp3 прямо в браузере — для проверки на компьютере.

- **Синхронизация** — `src/sync/`: триггеры SQLite записывают в журнал `sync_outbox`, что поменялось; движок отправляет это на сервер и применяет чужие правки (из двух — более поздняя). Сервер — `server/` (Fastify + Postgres), про данные внутри записей он ничего не знает.

- **Версия для компьютера** — Electron, папка `desktop/`. Внутри тот же интерфейс и тот же веб-движок; главный процесс даёт только то, чего нет в браузере: папки с музыкой на диске (с слежением за изменениями), базу в файле, трей, кнопки на панели задач, загрузку с YouTube через yt-dlp. Мост к нему — `src/native/desktop/bridge.ts`.

Главное правило: TypeScript решает, **что** играть; движок решает, **как**. Музыка и запись прослушиваний не зависят от того, открыт ли интерфейс.

## Папки

```
src/
  app/          роутер, запуск (boot.ts), переходы экранов (motion.ts), ярлыки, автобэкап, недельные итоги
  design/       токены тёмной, светлой и AMOLED-тем, базовые стили и формы
  components/   строка трека, обложка, звёзды, списки, шторки, волна
  features/     экраны: home, library, search, top, chronicle, player, settings, onboarding
  domain/       чистая логика: перемешивание, радио, дуэли, недели, умные плейлисты, миксы, уборка тегов
  data/         база: схема (migrations.ts), Kysely через мост (db.ts), запросы, бэкап JSON
  native/       контракт с движком, его веб-версия и мост к приложению для компьютера (desktop/)
  stores/       Pinia: library, player, playlists, radio, settings, sync, ui
  sync/         синхронизация: что и как уходит на сервер (kinds.ts), обмен (engine.ts), запросы (api.ts)
tests/          Vitest для domain/ и разбора ID3

server/         сервер синхронизации: Docker, Fastify, Postgres — развёртывание в server/README.md

desktop/        приложение для Windows (Electron)
  main.ts       окно, папки с музыкой, отдача файлов плееру (app://amber/__media, с перемоткой), база, трей
  preload.ts    мост для страницы (window.amberDesktop)
  youtube.ts    загрузка с YouTube через yt-dlp
  build.mjs     сборка в desktop/app; установщик — electron-builder.json

android/app/src/main/java/app/yantar/player/
  core/         MusicCorePlugin: команды, события, SQL-мост, файлы, бэкап
  db/           Database: единственный владелец SQLite
  library/      Scanner (MediaStore), Id3Reader/Id3Writer, Mp4Tagger (теги m4a), TagFiles (безопасная запись),
                TrackKey (отпечатки файлов), TextFix (кириллица из CP1251), Covers
  playback/     Engine (две деки, переходы, эквалайзер), PlayerHub, PlaybackService, Preview, виджет
  analysis/     Analyzer: громкость LUFS, тишина по краям, волна, темп
  tracking/     PlayTracker: каждое прослушивание в play_events
```

Схема базы описана один раз, в `src/data/migrations.ts`. Kotlin пишет только в `tracks`, `play_events`, `analysis` и `track_user` (кнопка ❤ в уведомлении).

## Проверить в браузере через Docker

Нужен только Docker Desktop.

```bash
docker compose up --build
```

Открыть http://localhost:8095. При первом запуске можно выбрать **«Открыть папку с музыкой»** (Chrome или Edge: папка запоминается, теги можно записывать в файлы) или **«Попробовать на демо-треках»**. Файлы читаются прямо в браузере и никуда не отправляются. Данные веб-версии живут в IndexedDB браузера.

Режим разработки с горячей перезагрузкой: `docker compose --profile dev up dev` → http://localhost:5173.

## Amber на компьютере (Windows)

Тот же Amber в отдельном окне: медиатека, рейтинг, статистика, хроника, миксы, эффекты — всё как на телефоне, плюс то, что нужно на ПК:

- окно собрано из стеклянных панелей с зазорами поверх фона в цветах обложки: меню с разделами и плейлистами слева, сцена с экраном посередине, панель «Сейчас играет» справа (обложка, оценка, избранное, текущие строки текста, что дальше; сворачивается кнопкой в строке заголовка, в окне уже 1300 px её нет), плеер — плавающей панелью над низом сцены; очередь выезжает справа, шторки — диалогами;
- строка заголовка окна занята делом: «назад / вперёд» по экранам и поле поиска (Ctrl+F) — набираешь, и открывается раздел поиска с результатами;
- раскладки под ширину окна, а не растянутый телефон: главная — плиткой, шапки альбомов, исполнителей, плейлистов и страницы трека — горизонтальные, большой плеер в две колонки (обложка слева, управление, текст и «дальше» справа), списки треков — таблицами (альбом, третья колонка по смыслу списка, оценка, длительность), исполнители, плейлисты, папки, жанры, эпохи и «Оценить» — сетками карточек, обзор хроники, настройки и страница трека — в две колонки;
- несколько папок с музыкой на диске; новые и удалённые файлы приложение замечает само;
- теги пишутся прямо в файлы, удаление — в корзину Windows;
- крестик прячет окно в трей (музыка играет), выход — из меню значка или Ctrl+Q; кнопки «назад / пауза / вперёд» в миниатюре на панели задач;
- клавиши мультимедиа и плитка «Сейчас играет» Windows; горячие клавиши: пробел, Ctrl+←/→, Shift+←/→ (перемотка), Ctrl+↑/↓ (громкость), Ctrl+F, Ctrl+L, Esc;
- выбор устройства вывода (колонки, наушники), у каждого может быть свой эквалайзер;
- очередь и место в треке переживают перезапуск;
- загрузка с YouTube: при первом использовании скачивается утилита yt-dlp, файлы ложатся в «Музыка/Amber» (звук YouTube приходит фрагментированным MP4 — приложение пересобирает его в обычный m4a и пишет теги с обложкой);
- голосовые команды (включаются в настройках, «Окно»): «Эмбер, стоп / продолжи / следующий / назад / тише / громче / лайк». Распознавание офлайн — модель Vosk (~45 МБ) скачивается при первом включении в папку данных; услышав «Эмбер», плеер приглушает музыку, пока ждёт команду. Отладка: `localStorage.amberVoiceDebug = '1'` — услышанное и уровень микрофона в консоль;
- живой фон в цветах обложки и матовое стекло панелей, плеера, заголовков и шторок (подкраска, светлая кромка сверху, тень в цвет фона, лёгкое зерно); подсветка в такт басам выключается в настройках («Окно»), размытие выключается переключателем «Стекло» во «Внешнем виде» — для слабых видеокарт.

Анализ треков (громкость, волна, тишина по краям, темп) идёт кусками по три минуты, а у треков длиннее получаса — по 40 окнам выборкой: память не зависит от длины, десятичасовой трек анализируется так же спокойно, как обычный. Если страница всё же упадёт посреди анализа, окно перезагрузится само, а при следующем запуске этот трек будет пропущен.

```bash
npm run desktop        # собрать и запустить окно
npm run desktop:pack   # установщик: release/Amber-Setup-<версия>.exe
```

Данные живут в `%APPDATA%\Amber`: база `amber.sqlite` (и копия `.bak` с прошлого запуска), список папок и настройки окна `desktop.json`, журнал падений `amber.log`.

База пишется с fsync (сначала во временный файл, потом подмена), поэтому выключение из розетки не оставляет вместо неё мусор. Если файл всё же повреждён, при запуске он откладывается как `amber.sqlite.broken-<дата>` (не удаляется), а Amber открывает копию `.bak` с прошлого запуска и говорит об этом. Вернуть вручную: закрыть Amber, переименовать `amber.sqlite` и положить на его место копию `amber.sqlite.bak`.

На телефоне база в режиме WAL, который при внезапном выключении теряет максимум последние записи, но не портит файл. Сверх этого раз в день делается копия базы (`files/db-backup`, две последние). Если база не открывается, она откладывается как `yantar.db.broken-<дата>`, а Amber берёт последнюю копию. Стандартный обработчик Android в таком случае удалил бы базу вместе со всей историей. Историю с телефона можно перенести бэкапом: «Экспорт в JSON» на телефоне → «Импорт из JSON» на компьютере (треки совпадают по содержимому файла, а не по имени).

Для проверок: `AMBER_USER_DATA` — своя папка данных, `AMBER_YT_DIR` — куда класть скачанное с YouTube, `AMBER_HIDDEN=1` — окно за краем экрана и без фокуса; отладка страницы — `--remote-debugging-port=9334`.

Если Electron запускается из терминала VS Code и вместо окна печатает версию Node — в окружении осталась переменная `ELECTRON_RUN_AS_NODE`; её нужно убрать.

## Команды

```bash
npm install          # зависимости
npm run dev          # интерфейс в браузере: http://localhost:5173
npm test             # тесты логики (Vitest)
npm run lint         # ESLint
npm run format       # Prettier
npm run build        # проверка типов + сборка веб-части в dist/
npm run apk          # сборка + cap sync + debug-APK
```

Для `npm run apk` нужны JDK 21+ (`JAVA_HOME`) и Android SDK (путь в `android/local.properties`).
Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`.

## Сборка на GitHub Actions

Workflow `.github/workflows/ci.yml` на каждый пуш и pull request:

1. линтер, форматирование, тесты и веб-сборка;
2. APK — лежит в **Actions → запуск → Artifacts → amber-apk**;
3. Docker-образ (проверка, что собирается).

Тег вида `v0.2.0` создаёт релиз с APK. Debug-APK подписан постоянным ключом из репозитория, поэтому новые версии ставятся поверх старых без потери данных. Для подписи релизного APK своим ключом добавь секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.

## Установка на телефон

1. На телефоне: Настройки → Сведения о телефоне → Сведения о ПО → семь раз нажать «Номер сборки». Появятся «Параметры разработчика».
2. В «Параметрах разработчика» включить «Отладка по USB» и подключить телефон кабелем.
3. `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`

Можно и без кабеля: скачать APK из Actions на телефон и открыть его, разрешив установку из этого источника.

После установки стоит поставить приложению батарею «Без ограничений» (Настройки → Приложения → Amber → Батарея), чтобы One UI не усыплял музыку. Кнопка есть и в настройках приложения.

## Отладка

- Интерфейс внутри телефона: Chrome на компьютере → `chrome://inspect` → WebView Amber.
- Нативная часть: `adb logcat | grep -iE "yantar|PlayerHub|Engine|AndroidRuntime"`.
  На каждом переходе между треками Engine пишет, через сколько мс реально зазвучал следующий трек.

Приложение называется Amber, но идентификатор пакета остался `app.yantar.player`: так новая версия ставится поверх старой и сохраняет историю.
