# Сервер синхронизации Amber

Свой маленький сервер, через который телефон и компьютер обмениваются данными Amber. Аккаунт — почта и пароль.

**Что синхронизируется:** оценки, избранное, заметки и настройки треков (обрезка краёв, своя громкость), история прослушиваний, история изменения оценок, дуэли, метки в треках, эпохи, контексты, плейлисты (вместе со стыками миксов), их группы, закрепление, порядок и обложки, дневник, тексты песен, скрытые подсказки и общие настройки: правило «что считать прослушиванием», пресеты звука, радио, вид перемешивания, когда спрашивать оценку, показ текста и поиск текстов в LRCLIB.

**Что не синхронизируется:** сами треки (их на сервере нет вообще), папки, эквалайзер и профили вывода, тема, громкость, очередь, свёрнутые группы, голосовые команды — то, что у каждого устройства своё.

**Изменения доходят сразу.** Каждое устройство держит открытым поток событий сервера (`/v1/events`). Поставил оценку, поменял плейлист или его обложку, сохранил пресет звука, доиграл трек — запись уходит на сервер в ту же секунду, сервер будит остальные устройства аккаунта, и те забирают её обычной синхронизацией. На открытом приложении это доли секунды. Телефон с погашенным экраном Android может придержать: тогда всё придёт, как только приложение снова окажется на экране.

**Что играет на других устройствах.** По тому же потоку сервер пересылает, что играет на каждом устройстве аккаунта, и команды между ними: пауза, следующий трек, перемотка, «играй отсюда». Звуковой движок телефона держит свой поток, поэтому телефоном можно управлять с компьютера и с погашенным экраном (после 10 минут паузы телефон отпускает соединение и пропадает из списка до следующего запуска музыки). Это состояние живёт только в памяти сервера: после перезапуска устройства переподключаются и присылают его заново. Нужен сервер версии 0.3 и новее.

**Без сети всё работает как раньше.** Изменения копятся в журнале на устройстве и уходят сами, когда появляется связь: при запуске, при возвращении сети, при разворачивании приложения и про запас раз в три минуты. Если одну и ту же запись поменяли на двух устройствах, остаётся более поздняя правка.

Сервер версии 0.1 потока событий не знает: приложение с ним работает, но чужие изменения приходят раз в несколько минут (в настройках синхронизации об этом будет строка). Обнови сервер — см. «Обновление» ниже.

Треки совпадают между устройствами по содержимому файла, а не по имени: оценка на телефоне находит тот же трек на ПК, даже если файл переименован. Если трека на другом устройстве нет, приходит его карточка — название, исполнитель, альбом, длительность (без обложки): в истории, топе и статистике трек виден, а в медиатеке нет. Появится сам файл — сканер найдёт его по содержимому, и история с оценкой окажутся на месте.

## Что внутри

```
docker-compose.yml   два контейнера: api (Node 24, Fastify) и db (Postgres 17)
Dockerfile           образ api — без сборки, Node сам запускает TypeScript
.env.example         пароль базы и настройки регистрации
src/main.ts          запуск, переменные окружения
src/app.ts           все запросы: регистрация, вход, устройства, синхронизация
src/db.ts            схема Postgres
src/auth.ts          пароли (scrypt) и токены
test/                сквозные тесты: сервер + два «устройства» на настоящей схеме приложения
```

API наружу не торчит: контейнер слушает только `127.0.0.1:8096` на самом сервере, а https и домен даёт nginx, который у тебя уже стоит.

## Развёртывание

Нужны Docker с плагином compose (`docker compose version`), nginx и https — всё это у тебя уже есть для gym.

### 1. Положить код на сервер

Если репозиторий на GitHub — проще всего клонировать:

```bash
git clone https://github.com/LegionLiner/amber.git ~/amber
cd ~/amber/server
```

Или скопировать только папку `server` с компьютера (Git Bash или PowerShell):

```bash
cd music_app
tar --exclude=node_modules --exclude=.env -czf amber-server.tgz -C server .
scp amber-server.tgz user@сервер:~/
ssh user@сервер 'mkdir -p ~/amber-server && tar -xzf ~/amber-server.tgz -C ~/amber-server'
```

Дальше все команды — в этой папке на сервере.

### 2. Настройки

```bash
cp .env.example .env
sed -i "s/^POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=$(openssl rand -hex 24)/" .env
cat .env
```

Пароль базы нужен только контейнерам, запоминать его не надо. Если порт 8096 на сервере занят, поменяй `AMBER_PORT` (и потом то же число в nginx).

### 3. Запуск

```bash
docker compose up -d --build
docker compose ps                         # оба контейнера — healthy
curl http://127.0.0.1:8096/v1/health      # {"ok":true,"version":"0.1.0"}
```

Контейнеры называются `amber-api-1` и `amber-db-1`, с проектом gym не пересекаются. После перезагрузки сервера поднимаются сами.

### 4. nginx

Выбери один из двух вариантов.

**А. Отдельный поддомен** (например `amber.example.com`). В DNS добавь A-запись поддомена на IP сервера, затем `/etc/nginx/sites-available/amber`:

```nginx
server {
    listen 80;
    server_name amber.example.com;

    # Первая синхронизация отправляет всю историю частями до нескольких мегабайт
    client_max_body_size 25m;

    location / {
        proxy_pass http://127.0.0.1:8096;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/amber /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d amber.example.com     # сертификат и переадресация на https
```

Адрес для приложения: `https://amber.example.com`.

**Б. Путь на домене gym** — без нового поддомена и сертификата. В уже существующий блок `server { listen 443 ssl; … }` gym добавь:

```nginx
    location /amber/ {
        client_max_body_size 25m;
        proxy_pass http://127.0.0.1:8096/;     # слэш в конце обязателен: /amber/v1/… → /v1/…
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

Адрес для приложения: `https://домен-gym/amber`.

Проверка снаружи (с компьютера): открой `https://…/v1/health` в браузере (для варианта Б — `https://домен-gym/amber/v1/health`) — должно показать `{"ok":true,…}`.

#### Если nginx у gym тоже работает в Docker

Тогда `127.0.0.1` внутри контейнера nginx — это сам контейнер, и до порта 8096 он не дотянется. Нужно подключить api Amber к сети, в которой живёт nginx. Узнай её имя: `docker network ls` (обычно `<папка-gym>_default`), и рядом с `docker-compose.yml` Amber создай `docker-compose.override.yml`:

```yaml
services:
  api:
    networks:
      default:
      web:
        aliases: [amber-api]

networks:
  web:
    external: true
    name: gym_default # имя сети nginx из docker network ls
```

```bash
docker compose up -d
```

В конфиге nginx вместо `http://127.0.0.1:8096` пиши `http://amber-api:8080` (в варианте Б — `http://amber-api:8080/`), потом перезагрузи nginx: `docker exec <контейнер-nginx> nginx -s reload`. Amber должен быть запущен раньше, чем nginx перечитает конфиг, иначе nginx не найдёт `amber-api`.

### 5. Войти в приложениях

1. **Первое устройство** (например, ПК): Настройки → Синхронизация → адрес сервера, почта, пароль (от 8 символов) → «Создать аккаунт». Всё, что уже есть на устройстве, отправится на сервер.
2. **Второе устройство** (телефон): там же → «Войти» с той же почтой и паролем. Придут данные с первого, а его собственные уйдут на сервер — история не затирается, а объединяется.

Внизу раздела видно, когда была последняя синхронизация, кнопка «Синхронизировать сейчас», список устройств (потерянное можно отключить) и удаление аккаунта со всеми данными на сервере. Выход ничего не стирает на самом устройстве.

### 6. Закрыть регистрацию

Когда аккаунт создан, чтобы никто чужой не заводил аккаунты на твоём сервере:

```bash
sed -i 's/^ALLOW_SIGNUP=.*/ALLOW_SIGNUP=false/' .env
docker compose up -d          # пересоздаст api с новой настройкой
```

Вход в существующий аккаунт продолжит работать. Если хочешь пустить кого-то ещё — либо верни `true` на время, либо оставь `true` и задай `SIGNUP_CODE=любой-код`: тогда в форме регистрации появится поле «Код приглашения», без которого аккаунт не создать.

## Обслуживание

```bash
docker compose logs -f api                  # что происходит
docker compose restart api                  # перезапуск
docker compose down                         # остановить (данные остаются в томе amber_pgdata)
```

**Обновление** — новая версия кода и пересборка, данные не трогаются:

```bash
git pull                     # или заново распаковать архив поверх
docker compose up -d --build
```

**Резервная копия** базы:

```bash
docker compose exec -T db pg_dump -U amber amber | gzip > ~/amber-$(date +%F).sql.gz
```

Каждую ночь в 4:00 (`crontab -e`, путь поправь на свой):

```
0 4 * * * cd ~/amber/server && docker compose exec -T db pg_dump -U amber amber | gzip > ~/backups/amber-$(date +\%F).sql.gz
```

Восстановление в пустую базу:

```bash
gunzip -c ~/amber-2026-10-05.sql.gz | docker compose exec -T db psql -U amber amber
```

Впрочем, полная копия данных есть и на каждом устройстве: если база на сервере пропадёт, достаточно выйти и снова создать аккаунт — устройство отправит всё заново.

## Безопасность

- Пароли хранятся как scrypt с солью. Устройство после входа получает случайный токен, в базе лежит только его SHA-256 — утечка базы не даёт войти.
- Не больше 10 попыток входа или регистрации в минуту с одного адреса.
- Наружу открыт только nginx с https; api и Postgres доступны лишь на самом сервере.
- Данные в базе не шифруются — это твой сервер, их видит только тот, у кого есть к нему доступ.

## Если что-то не так

| Что видно                                                     | Что делать                                                                                                 |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| В приложении «Нет связи с сервером»                           | Проверь адрес в браузере: `https://…/v1/health`. Для варианта Б адрес в приложении — с `/amber` на конце   |
| «Ошибка сервера» и в логах `413` / `Request Entity Too Large` | В nginx не хватает `client_max_body_size 25m;`                                                             |
| «Регистрация на этом сервере закрыта»                         | `ALLOW_SIGNUP=false` в `.env` — это и задумано; входи в существующий аккаунт                               |
| «Вход устарел: войди снова»                                   | Устройство вышло из аккаунта с другого устройства — просто войди снова, данные на месте                    |
| api не стартует, в логах «База в кодировке …»                 | Postgres создан не в UTF-8 (так бывает, только если подключать свою базу): создай базу с `--encoding=UTF8` |
| `port is already allocated`                                   | Порт 8096 занят — поменяй `AMBER_PORT` в `.env` и в nginx                                                  |

## Разработка

Без Docker, с Postgres прямо в процессе (PGlite, данные в папке `data/`):

```bash
cd server
npm install
DATABASE_URL=pglite:./data npm start        # http://localhost:8080
npm test                                    # сквозные тесты на PGlite
TEST_DATABASE_URL=postgres://… npm test     # те же тесты на настоящем Postgres (база очищается!)
npm run typecheck
```

Сервер не знает, что внутри записей: для него каждая — «вид, ключ, JSON, время правки на устройстве, удалена ли». Новые виды данных в приложении (`src/sync/kinds.ts`) сервер менять не требуют.

API (всё под `/v1`, токен в заголовке `Authorization: Bearer …`):

| Запрос                                                      | Что делает                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/health`                                            | жив ли сервер                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `POST /v1/auth/register` `{email, password, code?, device}` | создать аккаунт → `{token, email}`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `POST /v1/auth/login` `{email, password, device}`           | войти → `{token, email}`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `POST /v1/auth/logout`                                      | выйти на этом устройстве                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `GET /v1/me`                                                | аккаунт, число записей, устройства                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `DELETE /v1/devices/:id`                                    | выйти на другом устройстве                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `DELETE /v1/me` `{password}`                                | удалить аккаунт со всеми данными                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `POST /v1/sync` `{cursor, changes}`                         | отдать свои изменения, получить чужие после курсора → `{cursor, changes, more}`                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `GET /v1/events?role=ui\|engine`                            | поток событий (SSE): `hello` — открыт (с тем, что играет на остальных устройствах), `changed` — другое устройство прислало изменения базы, пора делать `/v1/sync`; `player` — что играет на другом устройстве (или `gone`); `command` — команда этому устройству. `role=engine` — поток звукового движка телефона: ему приходят команды управления плеером, интерфейсу (`ui`) — всё остальное. Раз в 25 с — пустая строка, чтобы прокси не рвал соединение; nginx поток не буферизует (заголовок `X-Accel-Buffering: no`), отдельной настройки не нужно |
| `POST /v1/player` `{state}`                                 | что играет на этом устройстве (трек, пауза, позиция, окно очереди ключами); `null` — ничего. Хранится, пока у устройства открыт поток событий                                                                                                                                                                                                                                                                                                                                                                                                           |
| `POST /v1/command` `{to, cmd, args}`                        | команда устройству `to`: `play`, `pause`, `toggle`, `next`, `prev`, `seek {ms}`, `takeover {state}` (собрать эту очередь у себя и играть). 404 — устройство не на связи, 409 — для `takeover` нужен открытый интерфейс                                                                                                                                                                                                                                                                                                                                  |
